# Протокол выполнения этапа (для свежего подагента)

Состояние переезда хранится в файлах и Linear, не в контексте. Начинаешь с чистого листа. Прочитай: этот протокол, `spec/README.md` (раздел «Правила ведения спеки»), `spec/_templates/`, [план и карту переноса](60-spec-restructure.md) (план — вверху, карта — внизу файла; читай только свои строки). Монолит (`spec/спецификация_взаимодействия_v2.md`, 752 строки) целиком не читай: только нужные диапазоны строк (`Read` с `offset` и `limit`) по карте.

**Экономия токенов.** Перенос текста делай скриптом на Python (вырезать диапазон строк по карте и записать в файл), а не переписывая вручную. Руками добавляй только то, что требует понимания: номера правил, TL;DR, параметры, ссылки, схему. Выводы команд ограничивай (`| tail -3`). Пути к файлам в Python-скриптах пиши в raw-строках (`r"C:\..."`) или с прямыми слэшами.

## Шаги для блока N

1. `git pull` в `botik-docs` (источник правды — GitHub).
2. Создай `spec/blocks/N-имя.md` по шаблону `spec/_templates/block.md`: шапка (`id`, `title`, `status`, `linear`), TL;DR (до 5 строк), таблица правил с номерами `B<N>-01…` по порядку появления (номера потом не меняются), «Связанное», ссылка «← К оглавлению».
3. **Статус в шапке:** `черновик`; если в блоке были пометки 🔴 — `на согласовании у Насти`. «Согласовано» ставит только Настя.
4. **Числа и времена** (окна, лимиты, часы, пороги) — в `spec/parameters.md` (создай или дополни): ID `P-…`, значение, константа в коде (ищи `grep` в `C:/Users/user/projects/botik`). В блоке — ссылка на параметр.
5. **Тексты Насти.** Если текст есть в `texts.py` или `prompts.py` — в блоке ключ и ссылка, цитату убрать. Если текста в коде нет — оставь цитату и пометь «ключа в texts.py нет». **Никогда не придумывай и не правь тексты Насти.**
6. **«Как сделано в коде».** Допущения, требующие подтверждения, и вшитые «решение Тимура/Насти …» → файлы `spec/decisions/YYYY-MM-DD-slug.md` по шаблону (`affects` — номера правил). Остальное удалить (код — источник); в карте статус «удалено (код — источник)».
7. **Пометки 🔴 и вопросы** — не создавай задач в Linear. Добавь строку в [60-open-questions.md](60-open-questions.md): блок и правило, суть, варианты ответа.
8. **Схема** — mermaid-диаграмма логики блока (только то, что есть в спеке). **Эталонные диалоги** — только те, что уже есть в спеке; не придумывай.
9. В монолите перенесённый раздел замени одной строкой «Перенесено → [blocks/N-имя.md](blocks/N-имя.md)».
10. В карте переноса (внизу `60-spec-restructure.md`) заполни колонку «Статус» для своих строк: `перенесено`, `удалено (причина)` или `в Linear (BOT-N)`.
11. Проверка: относительные ссылки между файлами спеки открываются (короткий скрипт); номера правил уникальны; у каждой своей строки карты есть статус.
12. Коммит и push в `botik-docs`: `git pull --rebase --autostash`, сообщение с префиксом `[timur-dev]` и номером `BOT-N`. **Без `Co-Authored-By` и упоминаний Claude.** Код `botik` не трогай, если этап этого не требует; если требует — тесты (`venv\Scripts\python -m pytest -q`), при падении не отправлять.
13. Linear: у своей подзадачи вызови `save_issue` только с `id` и `state: Done` (описание не передавай: инструмент возвращает его целиком). Если описание подзадачи содержит буквальные `\n` — перепиши его (один вызов): настоящие переводы строк, раздел «Спека» со ссылками на все затронутые файлы спеки на GitHub.

## Отчёт

3–5 строк: что сделано, коммиты, сколько вопросов добавлено в `60-open-questions.md`, что дальше.
