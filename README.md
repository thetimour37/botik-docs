# botik-docs

Бэклог, протоколы встреч и продуктовые материалы проекта **Ботик (Анастасия)**.
Код бота — в отдельном репозитории [`botik`](https://github.com/thetimour37/botik).

Методология разработки (циклы, DoD, версионные гейты) — см. `Методология разработки.md` в Obsidian-хранилище (вне этого репо).

## Локальная структура

Клонировать рядом с репозиторием кода, чтобы Claude Code мог читать оба репо в одной сессии по относительным путям:

```
C:\Users\user\projects\botik        — код
C:\Users\user\projects\botik-docs   — этот репозиторий
```

## Содержимое

```
botik-docs/
├── how-it-works-now.md              — как бот работает сейчас (компрессированный контекст), обновляется раз в 2-3 цикла
├── how-it-should-work-backlog.md    — бэклог: как бот должен работать (задачи и приоритеты)
├── roadmap.md                       — источник задач для Claude Code, обновляется по итогам ревью
├── meetings/                        — конспекты встреч, один файл на встречу (конспект_встречи_YYYYMMDD.md)
├── spec/                            — переработанное описание поведения бота + уточнения
│   └── clarifications/              — уточнения по темам
└── product/                         — canvases, анализ, примеры оформления
```

## Версионирование

Версии циклов (`v0.1`, `v0.2` … `v1.0`, `v2.0`) — это **git-теги**, синхронные с версией бота, а не отдельные папки. По завершении цикла (шаг Ship методологии):

```
git tag -a v0.2 -m "Итоги цикла: ..."
git push origin v0.2
```

Крупные версии дополнительно оформляются как **GitHub Release** (Releases → Draft new release → выбрать тег) — с текстом итогов цикла в описании. Это даёт снэпшот всех файлов на момент версии без дублирования папок: `git show v0.2:how-it-should-work-backlog.md` или кнопка «Browse files» на странице релиза.
