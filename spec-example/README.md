# Пример структуры спеки (черновик для проверки)

> Это демонстрация. Содержание сокращено и местами условно. После проверки папка `spec-example/` будет удалена.

Спека разбита на небольшие файлы. Переходить между ними можно по ссылкам: на GitHub и в Obsidian они работают одинаково.

## Оглавление

| Файл | Что в нём |
|---|---|
| [blocks/4-evening.md](blocks/4-evening.md) | Блок 4 «Вечер»: правила с номерами, схема, статус |
| [blocks/5-silence.md](blocks/5-silence.md) | Блок 5 «Молчание» (заглушка, чтобы показать ссылки между блоками) |
| [commands.md](commands.md) | Справочник команд бота и их поведение в разных состояниях |
| [parameters.md](parameters.md) | Все числа и времена в одном месте |
| [decisions/2026-10-14-evening-timeouts.md](decisions/2026-10-14-evening-timeouts.md) | Пример записи о принятом решении |

## Как устроено

- **Номера правил.** Каждое правило имеет номер вида `B4-02` (блок 4, правило 2). На него можно ссылаться из задач Linear, комментариев в коде и тестов. Номер не меняется, даже если правило перенесли.
- **Статус в шапке файла.** Видно сверху: черновик, на согласовании у Насти или согласовано.
- **Числа только в `parameters.md`.** В блоках стоит ссылка на параметр, а не само число. Меняем в одном месте.
- **Решения в `decisions/`.** Кто, когда и почему решил, и что было раньше.
- **Тексты Насти** хранятся в коде (`texts.py`). В спеке только ключ и ссылка, чтобы спека и бот не расходились.

## Как проверить, что ссылки работают

1. Откройте [blocks/4-evening.md](blocks/4-evening.md) и пройдите по ссылкам внутри: на параметры, команды, решение, соседний блок.
2. В каждом файле внизу есть ссылка «назад к оглавлению».
3. Откройте тот же файл в Obsidian и убедитесь, что переходы работают так же.
