# Команды бота

**Кратко (TL;DR).** Пользовательские команды режима 2, таблица «команда × состояние», служебные команды администраторов, скрытые и устаревшие команды, меню команд Telegram. Статусы реализации не ведутся в спеке (источник — задачи Linear). Режимы: режим 2 («осознанная рефлексия») — основной; режим 1 — старая логика (legacy).

## Пользовательские команды

| ID | Команда | Что делает | Блок |
|---|---|---|---|
| CMD-SETTINGS | `/settings` | Просмотр и редактирование контракта (время вечера); фокус здесь не меняется | [Блок 1](blocks/1-contract.md) |
| CMD-FOCUS | `/focus` | Текущий запрос (с последней оценкой 1–10) и фокус наблюдения (оценки по фокусу нет); смена фокуса в любой день кнопками «Предложи варианты» / «Свой фокус» — единственный путь смены | [Блок 3](blocks/3-daily.md) |
| CMD-DASHBOARD | `/dashboard` | Дашборд: динамика оценки запроса, регулярность и объём, текущий запрос и фокус; кнопка «Сменить фокус» ведёт в `/focus`. Форма (команда, мини-приложение Telegram или HTML) не решена | [Блок 7](blocks/7-monthly.md), [Блок 6](blocks/6-weekly.md) |
| CMD-PAUSE | `/pause` | Поставить анализ на паузу вручную: то же состояние `paused`, что кнопка «Мне бы паузу», с тем же признающим текстом Насти; выход — любое сообщение пользователя | [Блок 5](blocks/5-silence.md) |
| CMD-SESSION | `/session` | Запустить еженедельную сессию с психологом Анастасией, если она ещё не использована на этой неделе (название рабочее) | [Блок 6а](blocks/6a-session.md) |
| CMD-SUPPORT | `/support` | Благодарность, поддержка проекта | — |
| CMD-HELP | `/help` | Список команд; в конце — версия бота (например, «Версия бота: v2.1.0») | — |
| CMD-RULES | `/rules` | Правила, как работает бот. Текст зависит от глобального режима: режим 2 — описание формата из онбординга (экран 0.2, [Блок 0](blocks/0-onboarding.md)), режим 1 — прежний текст правил. В тексте правил есть упоминание команды `/bug` и зачем она (CMD-BUG) | [Блок 0](blocks/0-onboarding.md) |
| CMD-RELEASE | `/release` | Ссылка на список изменений (README на GitHub) | — |
| CMD-BUG | `/bug` | Сообщить об ошибке. Доступна **всем** (и пользователям, и администраторам, режимы 1 и 2). Бот просит описать проблему одним сообщением; следующее сообщение пользователя не уходит в нейронку и не считается наблюдением дня, а отправляется **только разработчику** (Тимуру; Telegram ID зашит константой `DEVELOPER_ID`, не `ADMIN_IDS`). Пользователю — подтверждение. Отчёт — **одно сообщение**, которое можно целиком переслать в нейронку: начинается с инструкции «Возьми в работу этот баг и внеси его в систему учёта багов по проекту Botik», дальше текст пользователя и контекст — кто (ID, username, имя); режим и этап (`flow_version`, `bot_mode`, `flow_stage`, подэтапы вечера / недели / месяца / смены фокуса, `engagement_state`, состояние FSM, активная сессия); время (сейчас в GMT+3 и UTC, день недели, время вечера из контракта, `v2_started_at`, `last_user_message_at`); состояние (фокус, запрос, сообщений сегодня, даты последнего вечера и недельного итога); система (версия, коммит, окружение). Любая другая команда отменяет ожидание; ожидание не меняет текущий этап пользователя; кризисная проверка не отключается. Ожидание описания — [P-BUG-WAIT-MIN](parameters.md); после него сообщение снова обычное. Защита от спама: лимит отчётов в час на пользователя — [P-BUG-REPORTS-PER-HOUR](parameters.md); при превышении бот просит подождать и ничего не отправляет. Тексты — в `texts.py` | — |

## Служебные команды (только администраторы)

| Команда | Что делает |
|---|---|
| `/debug` | Версия бота с коммитом и ссылкой на страницу релизов на GitHub; глобальный режим: `1 — свободное общение` / `2 — регулярная рефлексия`. При перезапуске бота с новой версией админам приходит отчёт с блоком «Что изменилось» — release note из `release_notes/vX.Y.Z.md` репозитория бота |
| `/profile`, `/profileupdate` | Профиль пользователя и его обновление; только для администраторов: профиль остаётся фоном для нейронки |
| `/resetonboarding` | Перезапуск онбординга для себя: в режиме 2 — заново экраны 0.1/0.2 → контракт → запрос, переписка и профиль не затираются (как `/resetv2`); в режиме 1 — прежний сброс флага `onboarded` |
| `/resetv2 [id …]` | Сброс выбранных пользователей в «первый вход» режима 2 |
| `/resetv2 all` | Массовый перевод всех пользователей режима 1 (`flow_version=1`) на режим 2 |
| `/simulateday` | Режим 2: имитирует наступление времени вечернего резюме по контракту — запускает вечер ([Блок 4](blocks/4-evening.md)) для себя сразу, не дожидаясь времени из контракта и без правила «раз в день»; дальше поток обычный (уточняющие вопросы → резюме дня). Режим 1 — прежний «итог дня» |
| `/simulateweek` | Недельное резюме и суббота ([Блок 6](blocks/6-weekly.md)) для себя сейчас, в любом состоянии |
| `/simulatemonth` | Месячный срез ([Блок 7](blocks/7-monthly.md)) для себя сейчас, в любом состоянии, без правила «больше 10 дней» |
| `/simulate`, `/simulateyear` | Только режим 1 (старая вечерняя рефлексия и годовой итог); в режиме 2 не используются, отдельной команды вечера нет — это `/simulateday` |
| `/stats` | Статистика: пользователи, сообщения, лимит дня, даты |

| Команда | Состояние |
|---|---|
| `/progress` | Прогресс рефлексий за последние 10 дней. Только режим 1; в режиме 2 скрыта, регулярность и объём — в `/dashboard` ([решение](decisions/2026-10-14-progress-hidden-mode2.md)) |

## Меню команд Telegram

- Пока часть пользователей на старой логике (режим 1), меню разное. Меню по умолчанию — старое: `/rules`, `/help`, `/support`, `/bug`.
- Пользователям режима 2 — своё меню на их чат: `/focus`, `/dashboard`, `/session`, `/pause`, `/settings`, `/rules`, `/help`, `/support`, `/bug`. Ставится при запуске бота, при `/start` и при сбросе.
- Если в базе не осталось пользователей режима 1, меню режима 2 становится меню по умолчанию (его видят и новые пользователи до `/start`). Пока такие пользователи есть — по умолчанию старое. Пользователям в служебном режиме 1 при меню режима 2 по умолчанию ставится старое меню на их чат.
- Администраторам (`ADMIN_IDS`) — отдельное меню на их чат: обычное меню плюс служебные команды из раздела выше; обычным пользователям служебные команды в меню не показываются.
- Меню пересчитывается при запуске бота и после `/resetv2 all`. Команды и описания берутся из кода (`services/menu.py`); в BotFather вручную ничего менять не нужно.
